## 2. 计划实施的三项功能增强（待用户确认具体细节）

### 增强 1：入站图片按 magic bytes 修正后缀与 MIME

- **目标**：解决 QQ 网关统一将图片标为 `image/png`（及哈希名 `.png`）导致真实 JPEG/GIF/WebP 落盘扩展名和 `data:` URL MIME 失真问题。
- **做法**：
  - 复用 `tencent-connect/dsh-qqbot` 已验证的 `imageExtension(buf)` / `correctImageExt` 魔数嗅探逻辑（覆盖 PNG / JPEG / GIF87a·89a / RIFF+WEBP / BMP），放入 [src/qq/media-in.ts](../../src/qq/media-in.ts)；
  - 下载拿到 `downloaded.bytes` 后，对 `kind === 'image'` 先按真实字节覆盖 `mimeType`（如 `image/jpeg`、`image/gif`、`image/webp`、`image/bmp`）及 `ext`，再生成落盘文件名与 `imageDataUrl`。
  - 补充对应契约测试。

### 增强 2：斜杠命令英文别名兼容

- **目标**：在保持原有中文两字主命令不变的前提下，支持常见英文命令输入。
- **做法**：
  - 在 [src/commands/parse.ts](../../src/commands/parse.ts) 定义别名归一化表，将英文命令名（小写后）统一映射为内部中文主命令名：
    - `sessions` / `ls` → `会话`
    - `switch` / `ws` → `切换`
    - `new` / `reset` / `clear` → `新建`
    - `stop` / `abort` → `停止`
    - `status` → `状态`
    - `compact` → `压缩`
    - `model` → `模型`
    - `thinking` / `think` → `思考`
    - `permission` / `perm` → `权限`
    - `help` → `帮助`
    - `next` / `prev` → `下一页` / `上一页`
  - [src/commands/dispatch.ts](../../src/commands/dispatch.ts) 的路由与 `managesPaging` 无需重复分支。
  - **待确认**：`/帮助` 列表是否保持纯中文（别名作静默兼容），还是在条目后附注英文别名；同步更新 `tests/contract/commands.test.ts`。

### 增强 3：审批与 `ask_user_question` 的 QQ 卡片与按钮样式支持

- **目标**：将当前纯文本（`msg_type=0`）的审批与提问交互升级为 **Markdown 排版卡片 + 内联按钮（失败自动降级纯 Markdown + 始终保留 `y`/`n`/序号文本回复兼容）**，对应修订原 D34（交互消息放宽为支持 Markdown + 按钮，普通命令回执仍保持纯文本）。
- **做法**：
  1. **协议层（[src/qq/client.ts](../../src/qq/client.ts)、[src/types/qq.ts](../../src/types/qq.ts)）**：
     - `IDENTIFY` 增加 `QQ_INTENT_INTERACTION = 1 << 26`；
     - 监听 `INTERACTION_CREATE` 事件并暴露 `onInteraction`；
     - 封装 `acknowledgeInteraction(id, code)`（`PUT /interactions/{id}`）；
     - `QqSendMessagePayload` 支持可选 `keyboard` 字段，回复时兼容传入 `event_id: "INTERACTION_CREATE:<id>"`。
  2. **卡片渲染与状态（[src/inbound/interactions.ts](../../src/inbound/interactions.ts) + 独立纯函数渲染模块）**：
     - **审批卡片**：从关联会话最近事件按 `callId` 提取被审批工具参数/命令原文（`commandOf`），用 Markdown 代码块展示，附「允许一次 / 拒绝」按钮（短 `group_id` + 唯一 `nonce` 防旧卡或重复点击）；
     - **提问卡片**：单题/逐题发送 Markdown 编号列表；单选题带 2 列内联按钮（标签 ≤ 10 字截断），多选题不带按钮引导回复 `1,3`；支持用 `INTERACTION_CREATE:<id>` 作为下一题被动回复目标（若无按钮点击则沿用原 `msg_id`）；
     - **降级与双通道**：带 `keyboard` 发送失败时自动降级为无 `keyboard` 的纯 Markdown 发送；无论按钮是否点过，未决期间仍同时接受文本 `y`/`n`、题号、`/跳过`、`/取消`；
     - 可选顺手把 `<qqbot-cmd-input>` 用于列表/帮助快捷点击（如后续需要再单列）。
  3. **契约测试与真机验收**：先补 `qq/client`、`interactions` 契约测试，再实现并执行 `pnpm build` + `pnpm test`。
